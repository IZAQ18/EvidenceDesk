# Lightweight threat model

| Risk | MVP control | Residual risk / next step |
|---|---|---|
| Cross-tenant or over-classification disclosure | Tenant and classification are mandatory retrieval predicates; tests exercise both | Use database row-level security and authorization integration tests in production |
| Unauthorized source/history access | Original, page, conversation, feedback, and report routes repeat tenant, clearance, owner, and role checks | Add database row-level security and centralized policy decision logging |
| Prompt injection inside a document | Treat content as data; flag common patterns; no document-driven tools; fixed workflow; flagged answer passages never enter the external model request | Expand pattern and adversarial coverage; use a specialized detector only after measuring it |
| Malicious or oversized uploads | Protected staging, allowlist, byte/page/OCR-page/DPI limits, PDF signature and SHA-256 integrity checks, safe generated IDs | Antivirus/content disarm, true quarantine bucket/prefix, isolated parsers and OCR workers |
| OCR resource exhaustion | OCR only weak pages; bounded page count and DPI; upload/rate limits; durable job attempts and leases | Enforce container CPU/memory/time quotas, use SQS/dead-letter handling, and isolate workers in production |
| Misleading OCR output | Extraction method, page/word counts, warnings, page citations, and minimum-text checks | Confidence scoring, layout-aware OCR, and human review for consequential use |
| Unsupported model answer | Strict JSON, server-owned citation markers, authorized citation IDs, number/negation/term checks, extractive fallback | Mechanical checks are not semantic proof; add human-reviewed held-out evaluation and stronger entailment checks before a paid rollout |
| Provider cost abuse or outage | Daily request/token/cost reservations, timeout, bounded evidence/output, usage metadata, extractive fallback | Add provider-side hard budgets, distributed rate limiting, alerts, and tested circuit breaking |
| External-provider privacy | Gateway off by default; selected excerpts only; `store:false`; no tools; disclosure of provider boundary | Complete vendor/privacy review, subprocessors and retention terms; seek approved retention controls if required |
| Key theft or forged tokens | Constant-time API-key comparison; generic auth errors; configurable rate limit; RS256/JWKS, issuer, audience, expiry, and required-claim validation in OIDC mode | Short-lived tokens, identity-provider integration tests, Secrets Manager, WAF/API Gateway throttles |
| Verification/reset-link theft or replay | Purpose-bound random tokens stored only as hashes; short expiry; rotation; one-time conditional claim; password reset revokes all sessions; GET pages do not consume links | Real email-account compromise remains outside the app; add delivery alerts, edge abuse controls, and customer support verification |
| Invitation abuse or privilege drift | Admin-only creation/revocation and member review; recipient email match; bounded role/clearance schema; session revocation after access changes; password-confirmed removal and ownership transfer; owner protection; expiring rotating one-time token hashes; CSRF | Add invitation-volume alerts, periodic access certification, phishing-resistant step-up authentication, and enterprise directory/group lifecycle integration |
| Export or deletion misuse | Admin-only bounded current-workspace export excludes secrets and storage paths; deletion requires current password plus explicit confirmation and refuses shared owned workspaces; ownership transfer preserves shared data before account deletion | Add asynchronous encrypted expiring exports, phishing-resistant step-up authentication, cleanup retry, and retention/backup expiry evidence |
| Original-file path attack | Generated storage paths, filename separation, containment checks, atomic writes, authorized download endpoint | Encrypted S3 with per-tenant prefixes, restrictive IAM, object scanning, and retention controls |
| Sensitive data in logs | Log identifiers and counts, not questions or document text | Central redaction rules, access controls, retention policy, audits |
| Dependency/parser vulnerability | Minimal dependencies, CI tests | Pin/scan dependencies and container images; patch SLA |
| Local database/original loss | Persistent Docker volume; guarded integrity preflight/copy tool; encrypted, versioned, retained AWS data-plane template | Provision and accept the managed target, then prove snapshot/database and object-version restores |

Security controls here are illustrative engineering measures. They do not constitute a certification or a guarantee.
